# Database Schema

This page shows the ERD Builder Pro 3.5.x database structure for **pure PostgreSQL** mode, which Self-host and Cloud use. The structure comes from `prisma/schema.pg.prisma` in the application repository and has **44 tables**.

| Mode | Schema | Tables |
|------|--------|--------|
| **Pure PostgreSQL** (Self-host, Cloud) | `prisma/schema.pg.prisma` | 44 |
| **SQLite** (Desktop, CLI) | `prisma/schema.sqlite.prisma` | 47 |
| **Supabase** (legacy) | `prisma/schema.prisma` | 30 application tables + Supabase `auth` tables |

## Table Summary

| Table | Purpose |
|-------|---------|
| `users` | User accounts. In Cloud they map SSO identities and hold no local password. |
| `sessions` | Login sessions. |
| `user_preferences` | User preferences, such as the Desktop backup folder. |
| `mcp_oauth_clients`, `mcp_oauth_authorizations`, `mcp_oauth_tokens` | OAuth for Web MCP with the `local` provider. |
| `teams` | Team Workspaces. |
| `team_members` | Team members and their role (Manager or Staff). |
| `team_invitations` | Team member invitations. |
| `team_audit_events` | Audit records of Team changes. |
| `project_access_grants` | Per-Project member roles (Editor, Commenter, Viewer). |
| `projects` | Projects, owned by a user (Personal) or a Team. |
| `diagrams` | ERD files, including the DBML text (`dbml_source`). |
| `notes`, `drawings`, `flowcharts` | Notes, Drawings, and Flowcharts files. |
| `entities`, `columns`, `relationships` | Tables, columns, and relationships in an ERD. |
| `table_constraints`, `table_indexes` | ERD table constraints and indexes. |
| `entity_changes` | Version History for every file type. |
| `discussion_threads`, `discussion_messages`, `discussion_reads`, `discussion_contexts` | File and Project discussions. |
| `comment_threads`, `comment_messages`, `comment_reads` | Comments on objects inside files. |
| `notifications` | Notification center. |
| `storage_objects` | Uploaded images (Library). |
| `storage_usage` | Storage usage summary per workspace. |
| `backups` | Database Backup history. |
| `ai_providers`, `ai_models` | AI providers and the model catalog. |
| `user_ai_configs` | AI provider configuration with encrypted API keys. |
| `ai_chat_sessions`, `ai_chat_messages` | AI Assistant conversations. |
| `ai_system_prompts` | System Prompts. |
| `user_ai_rules` | AI Rules. |
| `cloud_ai_runtime_configs` | **Cloud only.** AI configuration sent by ERDBPro SaaS. |
| `cloud_ai_usage_periods`, `cloud_ai_usage_requests` | **Cloud only.** AI credit usage. |
| `user_trial_surveys` | **Cloud only.** Trial user survey. |

Cloud-only tables are still created in every PostgreSQL database, but they stay empty on Self-host.

## SQLite (Desktop and CLI)

The SQLite database uses the same tables, with these differences:
- No Web MCP OAuth tables (`mcp_oauth_*`), because Web MCP is not available on Desktop and CLI.
- DB Client tables: `db_accounts`, `db_catalogs`, `db_clients`, `db_client_layouts`, `db_client_queries`, and `sql_queries`.

The Team tables exist in the SQLite schema, but Team features are not active on Desktop and CLI.

## Supabase (Legacy)

Supabase mode uses Supabase Auth (`auth.users`) instead of `users` and `sessions`, and has no Team, notification, storage, or Web MCP OAuth tables. Its base schema is in `sql/supabase/schema.sql`, and the later tables are in `prisma/migrations` in the application repository.
